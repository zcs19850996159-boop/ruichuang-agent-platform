# 睿创多模态客服智能体：决赛演示手册

## 演示前一键准备

保持专用 SSH 隧道运行，然后双击 `决赛演示准备.command`，或执行：

```bash
./决赛演示准备.command prepare
```

工具会完成四项硬检查：Phase 3 readiness、核心依赖健康、比赛 Token 可用性、演示资产完整性；随后清理固定会话并预热两个决赛问题。任何一项不符合预期都会以非零状态退出，不应开始演示。

## 现场主线（约 5 分钟）

### 1. 比赛题图文回答

打开 `http://127.0.0.1:18877/workbench`，选择“比赛演示”，使用比赛 API Token 登录。

点击快捷问题“如何按照手册更换电池？”。

必须现场指出：

- 文本按模型生成过程实时出现；
- 每生成到 `<PIC>` 位置，正确手册图片就在对应段落中出现；
- 右侧显示 Competition Profile、`competition` 知识空间、知识版本、置信度、证据和校验结果；
- 预期路由为 `Manual27`，图片顺序为 `Manual27_1`、`Manual27_2`、`Manual27_3`，不转人工。

### 2. 多模态图片输入

新建会话，上传 `assets/Manual01_18.jpg`，输入：

> 结合我上传的图片，如何使用空调的等离子净化功能？

预期路由为 `Manual01`，返回 `Manual01_18`，不转人工。这里展示的是“用户图片输入 + 手册知识检索 + 手册图片证据”，不是单纯的 OCR。

### 3. 新手册自动入库

进入 `http://127.0.0.1:18877/admin`，使用 `final-demo` 租户的企业 Token 登录。

选择 `official-manuals` 知识空间，上传：

- 文件：`assets/人体工学椅手册.txt`
- 产品 ID：`ergonomic-chair`

依次点击：

1. “上传并解析”：文件只进入暂存区，线上知识不改变；
2. “执行质量评测”：展示文档、文本块、图片、缺失图片、重复率和阻断项；
3. “批准并发布”：批准者由当前登录身份确定，发布后原版本仍可回滚。

随后回到聊天工作台，选择“企业知识”，使用同一企业 Token 登录，选择 `official-manuals`，提问：

> 人体工学椅的腰枕按摩功能如何启用？

回答必须包含“插入 USB”，且不转人工。这证明新增官方 TXT 不需要人工切块或手工构建索引，但仍经过质量门禁与人工发布批准。

## 演示后复位与失败回滚

执行：

```bash
./决赛演示准备.command reset
```

它会清理固定会话，并在企业演示凭据可用时将 `official-manuals` 原子回滚到 `official-txt-v1`。已发布版本不可变，因此回滚只切换 active 指针，不删除历史版本。

只执行知识回滚：

```bash
./决赛演示准备.command rollback
```

只执行健康检查：

```bash
./决赛演示准备.command check
```

如果 Phase 3 进程本身在现场故障，双击：

```text
服务故障回滚到Phase2.command
```

它会先确认本机 `18877` 的监听进程确实是本项目的专用 SSH 隧道，再停止该隧道，并用另一把只能转发至服务器 `127.0.0.1:8877` 的密钥切换到保留的 Phase 2。回滚后使用：

```text
http://127.0.0.1:18877/ui
```

Phase 2 只有旧版演示页和官方兼容 API，不包含 Phase 3 的 `/workbench` 与 `/admin`。恢复 Phase 3 时双击：

```text
恢复Phase3.command
```

## 现场禁止事项

- 不在演示中展示或口述任何 Token；
- 不临时上传未知手册或未知图片；
- 不修改 Competition Profile 或 `competition-kb-v1`；
- 管理发布只操作 `final-demo / official-manuals`；
- 如果预检查失败，先恢复服务，不带故障开始现场演示。
